# burgr-sample-onion

[![CI](https://github.com/SolidOps/burgr-sample-onion/actions/workflows/ci.yml/badge.svg)](https://github.com/SolidOps/burgr-sample-onion/actions/workflows/ci.yml)

> *The AI writes the model, a deterministic generator writes the code, the tests decide.*

A user management API generated by [Burgr](https://github.com/SolidOps/burgr) from a YAML
model, with Burgr's complete template set, **Onion** (Domain, Application, Infrastructure,
Api and Tests projects, EF Core, public packages only), and the harness that keeps AI
agents on the model and the extension points.

## Run it

Requires the .NET 10 SDK.

```sh
dotnet tool restore          # burgr, pinned in dotnet-tools.json
dotnet burgr specs           # regenerates src/**/*.g.* and src/**/Framework/*.f.cs from specs/*.yaml
dotnet test UM.slnx
dotnet run --project src/UM.Api
```

Then `POST /self-user-creation/create-user`, `POST /authentication/login`, and `GET /users`
with the token… The CI regenerates the code and fails if it differs from the committed
files: generation is deterministic.

## What is where

| Path | Written by | Content |
|---|---|---|
| `specs/burgr.json` | hand | Four settings, among them `TemplatePackage`: the Onion set, downloaded from nuget.org. |
| `specs/*.yaml` | hand | The model: users, local accounts and invites, the `right` and `user_right` entities, a `preferences` value object, six services, their transients, a rule, a factory, events. |
| `src/**/*.g.cs`, `src/UM.Diagrams/*.g.puml` | burgr | Code that depends on the model: domain classes, repositories, DTOs, CRUD and service endpoints, `DbContext`, generated tests, class diagram. Never edited, never read. |
| `src/*/Framework/*.f.cs` | burgr | The set's light framework, the same for every model: `Result<T>`, unit of work, paging, rights, events, `ApiTestBase`. Read to understand a behavior, never edited. |
| `src/UM.Api/Program.cs`, `JwtTokenIssuer.cs` | hand | JWT authentication, SQLite, schema creation, registration of the layers. |
| `src/UM.Application/*.cs` | hand | The service methods, the rule, the factory and an event handler, as `partial` members of generated classes. |
| `src/UM.Domain/*.cs`, `src/UM.Infrastructure/*.cs` | hand | The calculated property, extra repository queries, rights seeded in the `DbContext`. |
| `src/UM.Tests/*.cs` | hand | Integration tests through the real endpoints, on top of the generated ones. |
| `src/*/*.csproj` | burgr once, then hand | Written by burgr for a new module, then never touched: package references go there. |
| `AGENTS.md`, `CLAUDE.md`, `.claude/` | burgr (`/harness:.`) | The harness: the model, the extension points, the framework contracts, how to test. A hook refuses reads and edits of `*.g.*` files, and edits of `*.f.*` files. |

## Change the model

Edit `specs/*.yaml`, run `dotnet burgr specs`, build: the compiler asks for the extension
points the change requires. [`AGENTS.md`](AGENTS.md) lists what the Onion set supports and
generates.
